## 🔴 P0 — LAUNCH BLOCKERS (all founder-action, none are code)

### P0-1. Android signing key still recoverable from git history
The keystore + plaintext password `irongym2026` were untracked (commit `3ddd4a4c`) but **remain in history** at `ab702d66` (blobs confirmed extractable: 2200 B + 201 B). Anyone with repo/history access can sign a malicious APK Android trusts as a real Giron update.
**Fix:** (1) generate a NEW keystore in EAS managed credentials, (2) rotate passwords, (3) `git filter-repo --invert-paths --path credentials.json --path android-keystore.jks` + force-push.

### P0-2. 152-ФЗ data residency — Neon Frankfurt is illegal for RU users
`docs/LEGAL_RF_CHECKLIST.md §3` flags it; DB host is `…eu-central-1.aws.neon.tech`. Migration to Yandex Cloud / VK Cloud is **planned, not started**. The checklist itself says do it now while the DB is empty.
**Fix:** `pg_dump` Neon → Yandex Managed Postgres, swap `DATABASE_URL` in Render, file the Roskomnadzor ПДн notification. Gates legal RU onboarding, not the technical deploy.

### P0-3. Prod env vars unverifiable from repo — monitoring + payments depend on them
- Error monitoring only fires if `SENTRY_DSN` **or** `TELEGRAM_BOT_TOKEN`+`TELEGRAM_CHAT_ID` set — else silent no-op (you're blind on crashes).
- Webhook **rejects every payment with 500** unless `YUKASSA_WEBHOOK_SECRET` set.
- `AI_VISION_MODEL` must be set or food-scan may route to a non-vision model.
**Fix:** set them in Render, then verify via `GET /health/sentry` + `GET /health/deep` + a YuKassa test webhook.

## 🟡 P1 — FIX-SOON (code; before real money/volume)

### P1-1. Render keep-warm is ineffective → 30-50s cold starts for everyone
`server/src/index.ts:536` — the in-process `setInterval(SELECT 1, 10min)` is frozen while the dyno sleeps, and an internal DB query isn't inbound HTTP, so it does NOT reset Render's 15-min idle timer. **Single most visible "app is broken" symptom.**
**Fix:** external pinger (UptimeRobot / cron-job.org / GitHub Action) hitting a health URL every 10-14 min. ~10 min of work, biggest UX win.

### P1-2. `/chat` fires ~16 DB queries/message, several large + uncached
`server/src/ai/chatContext.ts` — worst: `workoutExercise.findMany … take:1000` with sets joined (`:178`), `meal take:200` (`:237`), 2× `workout take:50` nested. Only the User row is cached (60s). Latency grows with account age; concurrent chatters saturate Neon.
**Fix:** cap `take:1000`→~100, cache the non-user context with short TTL, push "all completed sets" into a periodic rollup.

### P1-3. Mistral free-tier token quota is your FIRST hard ceiling
Production model = `mistral-small-latest` (cheap), but free tier = 1B tokens/month. 1000 active users × 10 msgs/day × ~8k tokens ≈ blows the quota in ~12 days. Per-message cost is bounded by message-count quota (10/day free, atomic — good) but NOT by tokens; one `program_creation` msg can burn ~150k tokens across the 5-iteration tool loop.
**Fix:** watch the Mistral meter; have DeepSeek/Yandex fallback ready (but see P1-5). Consider a daily token-spend ceiling per user.

### P1-4. Payment webhook double-credits on replay (audit M1, still open)
`server/src/routes/subscription.ts:246` destructures `transactionId` but never uses it; `endDate = now + days` recomputed each call, so a replayed signed body **extends the paid period** every time. Signature verification doesn't help (a valid body replays fine).
**Fix:** persist provider event/transaction id (unique), no-op if seen; or use provider's authoritative period-end.

### P1-5. The LLM provider-failover story doesn't apply to /chat at all
`routes/ai.ts:19` imports the Mistral client **directly**, bypassing `services/llm/router.ts` entirely (router is only wired to healthcheck + recipes). So `AI_PRIMARY_PROVIDER` / `AI_FALLBACK_CHAIN` / the Yandex adapter have **zero effect on the main chat**. If Mistral has an outage, there is no failover. Worse: if someone DID wire the router and set `AI_PRIMARY_PROVIDER=yandex`, all 42 tools silently break (Yandex adapter has no function-calling, logs at `debug`, returns `[]`).
**Fix:** either honestly document "router NOT wired to chat", or swap `ai.ts`'s import to the router AND add a `supportsTools` guard so tool-intents skip non-tool providers.

### P1-6. TOTP replay TOCTOU (audit M2, still open)
`schema.prisma` `UsedTotpCode` has no `@@unique([userId, code])`; both `auth.ts` + `user.ts` do non-transactional `findFirst`→`create`. Two concurrent requests with the same captured code both pass = 2FA-bypass race.
**Fix:** add `@@unique([userId, code])` + db push, treat P2002 as "replay detected".

### P1-7. iOS HealthKit shipped but hard-disabled behind a dead "Скоро" button
`HealthScreen.tsx:318` — every iPhone user who taps "Здоровье и часы" hits a greyed-out no-op button. The adapter + `@kingstinct/react-native-healthkit` dependency already exist — it's a deliberate UI lock, not missing code. Strands ~half the audience.
**Fix:** either flip iOS to `healthKitAdapter` (finish wiring), or rephrase so it's not a dead end.

### P1-8. First-run empty states are weak (brand-new user's first impression)
- Progress→Обзор shows "0 / 0 / 0 т / 0 мин" stat cards, no guidance.
- Workouts→Программы: `UserProgramsList` returns `null` with no programs → section just vanishes.
- The shared `EmptyState` component exists but is used in **zero** screens.
**Fix:** add first-run empty states (use the existing `EmptyState`) with a CTA into a starter workout.
