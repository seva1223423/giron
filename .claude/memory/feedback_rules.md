## Git

**Правило:** После каждого `git commit` сразу делать `git push origin master`.
**Why:** Пользователь смотрит на GitHub и видит устаревшие данные. Локальные коммиты без пуша воспринимаются как отсутствие работы. Однажды 5 коммитов пролежали локально несколько часов — пользователь заметил и был недоволен.
**How to apply:** Всегда `git commit -m "..." && git push origin master` в одной команде.

## Memory

**Правило:** После значимых изменений обновлять оба места:
1. `~/.claude/projects/C--Users-sevka/memory/` (глобальная memory)
2. `~/Projects/iron-gym/.claude/memory/` (memory в репозитории — резервная копия)

**Why:** Пользователь однажды вышел из VS Code и потерял memory — она была привязана к другой рабочей директории. Дублирование в репозитории гарантирует сохранность.
**How to apply:** Обновлять оба места синхронно. MEMORY.md — это индекс, не содержит сам контент.

## Рефакторинг экранов

**Правило:** При рефакторинге экрана — двигаться по паттерну:
1. Читать весь файл полностью перед началом
2. Определить логические блоки JSX → отдельные компоненты
3. Компоненты с локальным state/useMemo забирают своё состояние внутрь
4. Компоненты с доступом к стору читают стор напрямую (не пробрасывать через пропсы)
5. Оркестратор держит только: shared computed state, handlers, composition
6. Создавать в `{screen-folder}/components/` с `index.ts` re-export
7. Коммитить и пушить сразу

**Why:** Паттерн выверен на ProgressScreen (1993→105), HomeScreen (970→232), ActiveWorkoutScreen (909→234).

## Знание блоки в ai.ts

**Правило:** Блоки добавлять батчами по 20 штук, называть функции `getBlock{NNNN}` где NNNN = 4-значный номер с ведущими нулями. Последний добавленный блок: **1690**. Следующий с: **1691**.
**Why:** Последовательность важна для TF-IDF индексации. Пропуски в нумерации сломают логику выбора блоков.
